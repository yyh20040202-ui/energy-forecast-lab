# 项目讲解与复现清单

这是在 AI 编程辅助下搭建的个人学习原型。投递时可以写实际已经运行的模块与实验，不应称为企业实习、科研论文或生产部署。正式面试前，自己完成下面的复现和解释。

## 先亲自运行

1. 根据 README 创建 Python 环境，安装依赖并执行测试。
2. 下载数据，执行训练，将自己的 `results.json` 与仓库的参考报告比较。
3. 用 `examples/request.json` 调用 CLI，再用 FastAPI 调用相同样本，检查预测一致。
4. 解释一个样本的历史区间与标签区间，手算最后一次观测值基线。
5. 阅读 `data.py`、`model.py`、`train.py`，能指出标准化器拟合范围和早停选模位置。

## 面试问题

- 为什么不能把时间序列窗口随机打散划分？相邻窗口高度重叠，未来状态会流入训练集。
- 为什么验证窗口可以读取训练区间里的历史？预测发生时那些历史已经被观测到；真正不可共享的是未来标签。
- 目标单位是什么？Wh / 10 分钟。预测未来 6 个区间的用电量，不是直接预测 6 个瞬时功率点。
- 为什么有 Persistence 和 Ridge？深度模型需要和信息范围相同的简单模型比较；复杂度本身不能证明效果。
- TCN 如何保持因果性？卷积右侧补零产生的尾部被裁掉，位置 t 的表示只能依赖 t 及以前的输入。
- 感受野有多大？四个残差块，每块两层 kernel=3 卷积，dilation=1/2/4/8，感受野为 1+4×(1+2+4+8)=61 个采样点，覆盖 36 点历史窗口。
- 为什么预测加上最后一个目标值？以持续性预测为初始状态，学习未来变化量，训练开始时输出有合理基线。
- 单变量消融能证明什么？检查过去目标本身与环境信息各自的价值；一组随机种子不能支持统计显著性结论。
- 为什么同时报告 MAE、RMSE、sMAPE？MAE直观，RMSE更惩罚峰值误差，sMAPE提供相对量级参考；低负荷场景下相对指标仍需谨慎解释。
- 如果深度模型没赢基线？如实报告，检查数据规模、分布变化、峰值稀缺和超参数，下一步在验证集做预先定义的实验，不针对测试结果调参。

## 后续可自己扩展的实验

- 使用 3 个固定随机种子，报告均值和方差，而不是只拿最好一次。
- 对照 context=18/36/72，并保持相同测试目标范围。
- 增加 GRU 或 LightGBM；所有参数只能用验证集选择。
- 专门评估高能耗区间和不同时间段误差，补充可解释性分析。
- 为更多建筑或新的时间段建立外部测试集，再讨论应用范围。
